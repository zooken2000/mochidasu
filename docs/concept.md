# コンセプトと抽出ルール

## 一言で

自分を説明する言葉は、もう誰かが書いている。それを持ち歩けるようにする。

## 核になる考え

- **人の根本は変わらない。** 本人が当たり前すぎて気づいていない特徴を、過去に他人が書いた言葉から教える。
- **位置づけは自己理解の補助。** 面接用の自己PR文は作らない（中学の寄せ書きを面接で引用するのは不自然なため）。
- **本人の言葉は本人が作る。** 根拠の引用と問いかけを渡すと、本人から最近の似た経験が出てくる。面接などで話す言葉は、その経験から本人が作る。

## 画面で見せるもの

1. **あなたが当たり前だと思っていること**（結果画面の上部）
   - 強みの候補（短いラベル）
   - 根拠の引用（時期の古い順。いつ・どの紙かを添える）
   - 自分に聞いてみること（2〜3問）
2. **N件のうちM件**（結果画面の下部）：残した言葉の一覧、捨てた言葉の一覧、テキストでのコピー

画面の構成：入口（`/`）、読み込む（`/upload`）、自分の結果（`/result`・タブの中だけ）、サンプル（`/sample`）、使い方（`/how`）。

## 言語

- 画面は日本語と英語。URL の `?lang=ja|en` で決め、無ければブラウザの言語に合わせる（ブラウザには保存しない）
- 英語のときは、強みの候補の名前と問いかけを英語で書かせる（エージェントに `language` を渡す）
- 引用（人が書いた言葉）は、どちらの言語でも翻訳しない

## 素材

| 素材 | 入力 | 用途 |
|---|---|---|
| 写真（最大6枚） | 紙の種類（任意）、何年前（必須・既定0） | 寄せ書き・色紙・サンクスカードなど |
| 貼り付けた文章（1件・2000字まで） | 出どころ（任意） | ピアボーナスや Slack の感謝など、最近の言葉 |

「何年前」は、「8年間、別々の人が同じことを書いていた」という期間の計算に使う。写真からは推測できないので、本人に入れてもらう。

## 抽出ルール

エージェントの指示文（`packages/agent/mochidasu_agent/extractor/agent.py`）と対応している。

| 残す（keep = true） | 捨てる（keep = false） |
|---|---|
| 本人の人柄・行動・関わり方の具体的な記述 | 定型の挨拶だけ（お疲れさまでした、新天地でも頑張って など） |
| 何をしてくれて、どう助かったかが分かる感謝 | 本人に触れない内輪ネタ、書き手自身の近況 |
| | 絵やスタンプだけのもの |

- 原文のまま写す。要約・言い換え・誤字の修正はしない（前後の挨拶を落とすのはよい）
- 印刷された見出し・枠・「THANK YOU」などの飾り文字は読まない。手書きだけが対象
- 判読できない箇所は推測しない（`unreadable_count` に数える）

## 強みの候補（traits）のルール

- 残した言葉のうち、**2人以上の別々の書き手**が触れている特徴だけ
- 言葉が違っても、指しているものが同じならまとめる。時期や場所が違うつながりを優先する
- ラベルに誇張や評価を入れない
- 問いかけは、最近の似た経験を思い出せる具体的なもの（例：「最近の仕事で同じことをした場面は？」「これが裏目に出たことは？」）

## プログラムで保証していること（`verify.py`）

- 貼り付けた文章から取った言葉が原文に含まれない場合は、捨てる（空白の違いは無視）
- 強みの候補の根拠は、残した言葉だけに絞る。書き手が2人未満の候補は落とす
- 候補は根拠の多い順に最大4つ、問いかけは最大3つ

## 出力の型

正は `packages/agent/mochidasu_agent/extractor/schema.py`。

- `fragments[]`：`source`（素材番号）、`text`、`writer`、`keep`、`reason`、`confidence`（high / partial）
- `traits[]`：`label`、`fragment_indexes`、`questions`
- `unreadable_count`

画面側の型は OpenAPI から自動生成される（`packages/web/src/generated/extractor/`）。画面で使う形への変換は `packages/web/src/lib/reading.ts` の `fromExtraction`。
